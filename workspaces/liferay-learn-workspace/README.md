# Liferay Learn Workspace

## Orchestrator Integration

The `liferay-learn-site-initializer-oahs` client extension provisions the OAuth 2 application the import cron (`liferay-learn-etc-cron-1`) uses to push generated documentation HTML into DXP.

| Field | Value | Consumer |
| :--- | :--- | :--- |
| `externalReferenceCode` | `liferay-learn-site-initializer-oahs` (the CE key in `client-extension.yaml`) | `learn-local` provision step looks up the OAuth2Application row by this ERC. |
| `clientId` | Generated by DXP on first deploy; preserved on update | Written to `.learn-local/cron-env` as `LIFERAY_LEARN_ETC_CRON_LIFERAY_OAUTH_CLIENT_ID` |
| `clientSecret` | Generated by DXP on first deploy; preserved on update | Written to `.learn-local/cron-env` as `LIFERAY_LEARN_ETC_CRON_LIFERAY_OAUTH_CLIENT_SECRET` |
| Scopes | See `client-extensions/liferay-learn-site-initializer/client-extension.yaml` | Must cover every REST family the cron's `Main.java` calls. |

When DXP is reset (volumes destroyed and recreated), the OAuth pair is regenerated; the orchestrator's `up` and `reimport` always re-read the current pair before invoking the cron.
